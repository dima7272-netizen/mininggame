# Аудит Dig Get Stronger

Дата снимка: 2026-08-25. Аудит выполнялся только на чтение; GitHub, Google Sheets и Roblox не изменялись.

## Источники

- `configs/*.json`: 9 активных конфигов GitHub main, локальный HEAD `c1c0ea9afede2ae90c10a7da99bf6b4048127720`.
- [Google Sheets](https://docs.google.com/spreadsheets/d/18WZ3D1ffBmwmrQ5v3q4y0SY2aoBJDdrRR_bzGBjC3YI/edit?gid=1186989391#gid=1186989391): 20 листов; прочитан XLSX-снимок и сохранённый JSON preview. Это наблюдение, а не повторное чтение Roblox API.
- `roblox/ConfigService.lua`: серверный загрузчик DataStore `GameConfigs` и hot reload через `MessagingService`.
- `scripts/deploy_experience_configs.py`: публикация Roblox Experience Configs из `configs`.
- `.github/workflows/*`: DEV, PROD и ежедневный backup.
- `google-sheets/Code.gs`: прежний экспорт из таблицы.

## Карта зависимостей

```text
Rooms ───────────────┐
RoomDrops ──itemId── SellItems ──► ожидаемая цена предмета
   │                 │
   └── room.index ───┴───────────► экран комнат и наград

Pickaxes ────────────► цена/сила (формула итогового удара не найдена)
Pets ────────────────► цена/сила (способ объединения не найден)
Upgrades ────────────► цены/уровни (потребитель не найден)
Rebirth ─────────────► требования/бонусы (применение бонусов не найдено)
Arenas ──────────────► множители (порядок прогрессии не подтверждён)
Spiders ─────────────► параметры движения/атаки (потребитель не найден)
```

В репозитории нет игровых потребителей формул удара, питомцев, ребёртов, арен, дохода и времени. Поэтому симулятор показывает найденные исходные значения, но итоговую силу, удары и время помечает «формула не подключена».

Отдельный игровой потребитель `RoomDrops` также не найден: `roblox/ConfigService.lua` только загружает конфиг из DataStore. Не подтверждены выбор с возвращением, независимость 7–8 появлений, возможность повторов и правила верхней подставки. Редактор поэтому показывает вес/нормализованную вероятность одной выборки. Формула `1 - (1 - p)^n` доступна лишь как явно включаемое владельцем рабочее допущение и не объявляется найденной игровой механикой.

## Подтверждённые вычисления сервиса

1. Средняя цена предмета комнаты: `Σ(weight / Σweight × sellPrice)`. Источники данных: `RoomDrops.json` + `SellItems.json`; реализация: `lib/analytics.ts`.
2. Сумма весов пула: `Σ weight = 100`. Подтверждено текущими 46 комнатами и прежним валидатором `scripts/deploy_experience_configs.py`; реализация: `lib/validation.ts`.
3. Рост HP/награды между соседними комнатами — аналитическое отношение, а не игровая формула.
4. Средний доход комнаты использует `(minimumItemsPerRoom + maximumItemsPerRoom) / 2 = 7.5` только как явно подписанное допущение. Распределение количества предметов в игровом коде не найдено.

## Найденные риски

- `MobileDrill` стоит `2e15` после `TwinFireScythe` за `1e16`: цена падает на 80%, сила растёт.
- Комната 16: HP растёт в 20 раз, средняя цена предмета остаётся `13 120 000`.
- Комнаты 38–46: HP растёт примерно в 10 раз на шаг, ожидаемая награда — только на 1.8–4.3%.
- `beyondLastRoom.hpMultiplier = 1`, а `blockMaxHP = maxBlockHP = 1.3e+30`: возможное плато после комнаты 46.
- `Arenas` нельзя безопасно сортировать по ID как линейную прогрессию: назначение ID не найдено.
- В рабочем `CFG_Spiders` пять значений (`10`, `10`, `200`, `3`, `0.5`) расходятся с JSON preview (`9`, `0.32`, `20`, `4.5`, `0.38`). Сервис показывает все пять различий.
- `ConfigService.lua`, `Code.gs` и обязательный список deploy-скрипта перечисляют только 8 core-конфигов и не включают `Spiders`, хотя общий deploy загружает все JSON. До реального выпуска Spiders нужно обновить и проверить игровой загрузчик.
- Для DEV и PROD есть по два близких workflow (`deploy-*.yml` и `deploy-*-shared-key.yml`): перед подключением адаптера следует выбрать один поддерживаемый путь.
- Luau использует double: сервис не округляет десятичные JSON-значения, но Roblox всё равно ограничивает точность больших чисел на стороне игры.

## Выбор базовой версии

Стартовый неизменяемый снимок создан из GitHub main. Табличный preview хранится отдельно как `PROD_OBSERVED` и не объявляется подтверждённым PROD, потому что реального чтения Roblox API не было. Конфликт Spiders не разрешается автоматически.
